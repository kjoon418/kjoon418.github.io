개요

리플렉션을 본격적으로 사용하기 위해서는 애노테이션을 사용할 줄 알아야 한다.
이전 시간에 리플렉션에 대해 학습해봤으니, 이번에는 애노테이션 사용법을 알아보자.

애노테이션이란?

주석(Annotation)에서 유래되었다.
말 그대로 코드에 추가적인 정보를 제공하는 주석 역할을 한다.

개발자만 이해할 수 있는 주석과 달리, 애노테이션은 컴파일 시점 혹은 런타임 시점에 해석될 수 있는 메타데이터를 제공한다.
즉, 프로그램이 읽을 수 있는 주석이다.

애노테이션 정의하기

1. 애노테이션 정의 형식

public @interface MyAnnotation { ... }

@interface 키워드로 애노테이션을 정의할 수 있다.

애노테이션은 속성을 가질 수 있으며, 아래에서 확인할 수 있듯이 인터페이스와 문법이 비슷하다.

2. 애노테이션이 지닐 수 있는 데이터 타입

public @interface MyAnnotation {
	// int, float, boolean 등 기본 타입
	int number();

	// String
	String string();

	// 타입에 대한 메타데이터
	Class<MyClass> type();
	
	// Enum
	MyEnum myEnum();
	
	// 다른 애노태이션 타입
	AnotherAnnotation anotherAnnotation();
	
	// 위 타입에 해당하는 배열
	boolean[] booleans();
}

애노테이션은 데이터를 위와 같이 메서드 형태로 정의한다.

이 메서드는 매개변수를 지닐 수 없고, 반환 타입으로 void를 사용할 수 없다.
또한, 예외를 선언할(throws) 수 없다.

애노테이션이 지닐 수 있는 데이터의 타입은 다음과 같다.

  1. 기본 타입(Primitive type)
  2. String
  3. Class
  4. enum 타입
  5. 다른 애노테이션 타입
  6. 위 타입들에 대한 배열

3. default 값

public @interface MyAnnotation {
	// 값을 지정하지 않을 때 100이 대입된다
	int number() default 100;
}

default 키워드를 사용하면, 애노테이션 속성의 기본 값을 지정할 수 있다.

4. 상속

package java.lang.annotation;

public interface Annotation {
	// 동등성 비교
	boolean equals(Object obj);
	// 해시코드 반환
	int hashCode();
	// 문자열 표현 반환
	String toString();
	// 애노테이션의 타입 메타데이터 반환
	Class<? extends Annotation> annotationType();
}

모든 애노테이션은 java.lang.annotation.Annotation 인터페이스를 상속한다.

enum의 경우와 같이 묵시적으로 상속하므로, 별도로 명시할 필요는 없다.
Java 컴파일러가 @interface 키워드를 통해 정의된 객체에 대해, Annotation 인터페이스를 확장하도록 처리해준다.

애노테이션은 다른 애노테이션이나 인터페이스를 상속할 수 없고, 오직 java.lang.annotation.Annotation만 상속 가능하다.
따라서, 애노테이션 간에는 상속 개념이 존재하지 않는다.

애노테이션 사용하기

1. 애노테이션 사용 예시

@MyAnnotation(number = 30)
public class MyClass { ... }

이와 같이, 사용하고 싶은 대상에게 애노테이션을 붙일 수 있다.

애노테이션은 타입(클래스, 인터페이스), 메서드, 필드, 파라미터 등 다양한 곳에 붙일 수 있다.

2. value 속성

public @interface MyAnnotation {
	String value();
}

// 입력할 요소가 value 하나라면, 속성명을 생략할 수 있다
@MyAnnotation("Hello world!")
public class MyClass { ... }

// 위 코드는 다음과 같다
@MyAnnotation(value = "Hello world!")
public class MyClass { ... }

Java는 애노테이션의 value 속성에 한해서 위와 같은 축약을 허용한다.
입력할 요소가 딱 하나면서 그 이름이 value라면, 속성명을 생략할 수 있다.

3. 배열 속성

public @interface MyAnnotation {
	int[] numbers();
}

// 배열 요소가 하나라면, 중괄호를 생략할 수 있다
@MyAnnotation(numbers = 1)
public class MyClass { ... }

// 배열 요소가 여럿이라면 생략할 수 없다
@MyAnnotation(numbers = {1, 2, 3})
public class MyClass { ... }

배열 속성의 경우, 요소가 하나라면 중괄호를 생략해 값을 지정할 수 있다. (생략하지 않아도 무방하다.)

메타 애노테이션

1. 메타 애노테이션이란?

@Retention(RetentionPolicy.RUNTIME) // ← 메타 애노테이션
public @interface MyAnnotation {
}

애노테이션을 정의하는데 사용하는 특별한 애노테이션을 메타 애노테이션이라고 부른다.

2. @Retention

// 소스 코드에만 남아있고, 컴파일 시점에 제거된다
@Retention(RetentionPolicy.SOURCE)
public @interface MyAnnotation {
}

// 컴파일 후 .class 파일까지는 담아있지만, Java 실행 시점에 제거된다
@Retention(RetentionPolicy.CLASS)
public @interface MyAnnotation {
}

// Java 실행 중에도 남아있다
@Retention(RetentionPolicy.RUNTIME)
public @interface MyAnnotation {
}

애노테이션의 생존 기간을 지정하는 메타 애노테이션이다.
value 속성으로 RetentionPolicy를 지정하면 되며, 값마다 다음과 같이 동작한다.

정책설명
SOURCE애노테이션이 소스 코드에만 남아있는다.
컴파일 시점에는 제거된다.
CLASS애노테이션이 컴파일된 .class 파일에까지 남아있는다.
Java 실행 시점에 제거된다.
기본 값이므로, 지정하지 않으면 이 정책으로 동작한다.
RUNTIME애노테이션이 Java 실행 중에도 남아있는다.
리플렉션 등에 활용하기 위해선 이 정책을 사용해야 한다.

3. @Target

// 클래스 혹은 인터페이스에 적용할 수 있다
@Target(ElementType.TYPE)
public @interface MyAnnotation {
}

// 메서드에 적용할 수 있다
@Target(ElementType.METHOD)
public @interface MyAnnotation {
}

애노테이션을 적용할 수 있는 위치를 지정하는 메타 애노테이션이다.

@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.ANNOTATION_TYPE)
public @interface Target {
	ElementType[] value();
}

Target 애노테이션은 ElementType[]을 지니고 있으니, 애노테이션을 다양한 위치에 적용 가능하게 만들 수도 있다.

public enum ElementType {
	TYPE,
	FIELD,
	METHOD,
	PARAMETER,
	CONSTRUCTOR,
	LOCAL_VARIABLE,
	ANNOTATION_TYPE,
	PACKAGE,
	TYPE_PARAMETER,
	TYPE_USE,
	MODULE,
	RECORD_COMPONENT;
}

ElementType의 종류는 위와 같다.

4. @Documented

@Documented
public @interface MyAnnotation {
}

해당 애노테이션이 적용된 요소에 대한 API 문서(Javadoc)에, 해당 애노테이션의 존재를 표시하게 만든다.
@Documented가 지정되지 않으면, Javadoc 도구가 문서를 생성할 때 해당 애노테이션 정보를 제외한다.

5. @Inherited

5-1. 상속이 되는 경우와 안 되는 경우
// 이 애노테이션이 자식 클래스에게까지 상속된다
@Inherited
public @interface MyAnnotation {
}

// 클래스의 상속에는 애노테이션이 상속된다
@MyAnnotation
public class ParentClass { }

public class Child extends ParentClass { } // Child에도 MyAnnotation이 적용된다

// 인터페이스의 구현에는 애노테이션이 상속되지 않는다
@MyAnnotation
public interface ParentInterface { }

public class Child implements ParentInterface { } // Child에 MyAnnotation이 적용되지 않는다

@Inheried는 해당 애노테이션을 자식 클래스에게까지 상속하도록 만드는 역할을 한다.

단, 클래스 상속에서만 동작하고, 인터페이스의 구현체에는 동작하지 않는다.

5-2. 인터페이스 구현에는 왜 적용되지 않을까?

클래스의 상속은, 자식 클래스가 부모 클래스의 속성과 메서드를 상속받는다는 개념이다.
즉, 자식 클래스가 부모 클래스의 특성을 이어받는다.

  • 때문에, 부모 클래스에 정의된 애노테이션을 자식 클래스가 상속받는 것이 자연스럽다.

반면 인터페이스는 메서드의 시그니처를 정의할 뿐, 상태나 행위를 가지지 않는다.

  • 때문에, 구현체가 인터페이스의 애노테이션을 상속받는 것이 어색하다.
  • 따라서, 인터페이스의 어노테이션을 구현체가 상속받지 않도록 설계되었다.

애노테이션 조회하기

Class<MyClass> myClass = MyClass.class;

MyAnnotation annotation = myClass.getAnnotation(MyAnnotation.class);

Class, Method, Field에는 getAnnotation, getAnnotations, getDeclaredAnnotation, isAnnotationPresent 등의 메서드가 존재한다.

해당 메서드를 통해 클래스/메서드/필드에 적용된 애노태이션들을 조회할 수 있다.

Java가 기본으로 제공하는 애노테이션

1. @Override

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.SOURCE)
public @interface Override {
}

메서드 재정의가 정확한지 컴파일러가 확인할 때 사용한다.

그렇기 때문에, RetentionPolicy.SOURCE를 사용해서 컴파일 시점에 제거한다.

2. @Deprecated

@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(value={CONSTRUCTOR, FIELD, LOCAL_VARIABLE, METHOD, PACKAGE, MODULE, PARAMETER, TYPE})
public @interface Deprecated {
	String since() default "";
	boolean forRemoval() default false;
}

더는 사용을 권장하지 않는 요소를 표시할 때 사용한다.

주로 다음과 같은 이유로 @Deprecated를 사용한다.

  1. 해당 요소가 잠재적인 문제점을 지니고 있다.
  2. 향후 버전에서 호환되지 않거나 제거될 수 있다.
  3. 더 나은 최신 요소로 대체되었다.
  4. 더 이상 사용되지 않는 기능이다.

각 속성은 다음과 같다.

  • since: 더 이상 사용하지 않게 된 버전의 정보를 의미한다.
  • forRemoval: 향후 버전에 제거될 것인지 여부를 의미한다.

3. @SuppressWarnings

@Retention(RetentionPolicy.SOURCE)
public @interface SuppressWarnings {
	String[] value();
}

Java 컴파일러의 경고를 억제(Suppress)할 때 사용한다.

개발자가 해당 문제를 잘 알고 있기 때문에 컴파일러가 경고하지 않아도 됨을 나타낸다.

자주 사용되는 value는 다음과 같다.

값설명
unused사용되지 않는 변수/메서드/필드에 대한 경고를 억제한다.
deprecation사용이 권장되지 않는 코드에 대한 경고를 억제한다.
rawTypes제네릭 raw 타입에 대한 경고를 억제한다.
unchekced제네릭 타입과 관련된 캐스팅 경고를 억제한다.
ex) List<String> strList = (List<String>) rawList;
all모든 경고를 억제한다.

마치며

애노테이션 역시 리플렉션처럼 활용은 무궁무진하지만 기본 문법은 단순하다.
이제 리플렉션과 애노테이션을 모두 사용할 수 있으니, Spring Framework가 제공하는 다양한 기능을 직접 만들어볼 수 있을 것 같다.
다음에 기회가 된다면, 이전에 직접 만든 프레임워크를 개선하며 새로운 기능을 추가해봐야겠다.
