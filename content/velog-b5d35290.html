저는 주 언어로 Java를 사용하다가 최근에 Kotlin으로 넘어왔어요.
Kotlin은 어쩌다가 Java 개발자들이 한 번 넘어가면 돌아오지 못하는 언어가 된걸까요?

가독성 측면에서 제게 가장 크게 와닿은 몇 가지 기능을 설명해드릴게요.
어려운 내용이 아니니, Kotlin을 아예 몰라도 이해할 수 있을거에요.

Named argument

Kotlin은 Named argument라는 문법을 지니고 있어요.
이 문법이 어떤 상황에 유용한지, Java와 비교해볼까요?

Java의 한계

public class User {
    String firstName;
    String lastName;
    String nickName;
    String location;

    public User(String firstName, String lastName, String nickName, String location) {
        this.firstName = firstName;
        this.lastName = lastName;
        this.nickName = nickName;
        this.location = location;
    }
}

이런 클래스가 있다고 가정해볼게요.
User 인스턴스를 생성하는 코드는 어떤지 볼까요?

// Jun은 뭐고 Kim은 뭐고 Watson은 뭔가요...?
User user = new User("Jun", "Kim", "Watson", "Seoul");

세상에나, 이런게 코드가 맞긴 한걸까요?
무슨 아규먼트가 어떤 역할을 하는지 파악하기 너무 힘들어요...
실수로 아규먼트 위치를 틀려도 파악하기 너무 오래 걸리겠네요.

// 조금 나아졌네요!
User user = User.builder()
		.firstName("Jun")
        .lastName("Kim")
        .nickName("Watson")
        .location("Seoul")
        .build();

Java는 이런 상황을 해결할 수 있도록 Builder 패턴이라는 해법을 내놨어요.
하지만 Lombok을 사용한다고 해도 User 클래스에 어노태이션을 붙여주어야 해서 번거롭고, builder()와 build() 메서드를 사용해야 해서 코드가 조금 지저분해져요.

Kotlin에서는 어떻게?

// Kotlin에서는 클래스를 이렇게 선언해요
class User(
    val firstName: String,
    val lastName: String,
    val nickName: String,
    val location: String
)

Kotlin에도 똑같이 User 클래스를 만들어 볼게요.

// 편할 뿐 아니라 가독성도 좋네요!
val user = User(
	firstName = "Jun",
	lastName = "Kim",
	nickName = "Watson",
	location = "Seoul"
)

Kotlin은 기본적으로 Named argument 문법을 지원하기 때문에, 별도의 코드 추가 없이도 User 인스턴스를 위와 같이 생성할 수 있어요

어느 아규먼트가 어떤 역할을 수행하는지 한 눈에 보여 가독성이 좋아지네요.

또한, 아규먼트의 순서를 바꾸더라도 문제되지 않는답니다.
(Builder와 동일한 장점이에요)

Default parameter

Default parameter 문법도 Java와 비교하며 알아볼까요?
콘솔에 Hello, <name>!을 출력하는 메서드를 만들어볼게요.
클라이언트가 name을 전달하지 않으면, 기본값으로 User를 사용할거에요.

Java는 기본값을 어떻게 구현하죠?

public class Greeting {
    void hello() {
        hello("User");
    }

    void hello(String name) {
        System.out.println("Hello, " + name + "!");
    }
}

콘솔에 Hello <name>!을 출력하는 hello 메서드를 만들었어요.
hello 메서드가 name 파라미터를 받지 않았을 때 기본값(User)을 사용하도록 하고 싶다면, 위와 같이 메서드를 오버로딩해서 모든 경우의 수를 구현해 주어야 해요.

위 상황에서는 파라미터가 1개이니까 메서드를 2개 만들어서 해결했지만, 파라미터가 더 많다면 모든 경우의 수를 다 구현할 수 있을까요?

Greeting greeting = new Greeting();

greeting.hello("Watson"); // Hello, Watson!
greeting.hello(); // Hello, User!

구현에 손이 많이 가지만 일단 동작은 하네요.
하지만 이게 최선일까요?

Kotlin에서는요?

class Greeting {
    fun hello(name: String = "User") {
        print("Hello, " + name + "!")
    }
}

Kotlin에서는 파라미터에 = "User"처럼 기본값을 할당해줄 수 있어요.
만약 클라이언트가 name 파라미터를 전달하지 않으면, name 파라미터에는 기본값인 User가 할당될거에요.

참고로 "Hello, " + name + "!" 부분을 간략하게 만들어주는 String template이라는 문법도 있는데, 궁금하면 찾아보세요!

val greeting = Greeting()

greeting.hello("Watson") // Hello, Watson!
greeting.hello() // Hello, User!

프로퍼티에 접근하는 방법

Java에서는 Getter와 Setter를 이용해서 속성 값을 조회하고 수정하죠.
Kotlin에서는 어떻게 달라졌는지 볼까요?

Java의 경우

public class Fruit {
    private String name;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}

직접 프로퍼티마다 Getter와 Setter를 구현해 주어야 해요.
값을 수정하지 못하게 하려면 Setter를 만들지 않으면 되겠죠?

Fruit fruit = new Fruit();

fruit.setName("Apple");
String name = fruit.getName(); // name = "Apple"

이것처럼 메서드를 이용해 프로퍼티를 조회하거나 수정할 수 있어요.
익숙한 방법이죠?

Kotlin의 경우

// 엥 이게 다에요?
class Fruit(
    var name: String
)

Kotlin은 놀랍도록 간단하게 프로퍼티에 접근할 수 있어요.
var는 값을 재할당할 수 있는 변수라는 뜻인데, 위와 같이 프로퍼티를 var로 선언하면 Getter와 Setter가 자동으로 구현돼요.
저희가 따로 만들어줄 필요 없답니다!

// 마치 프로퍼티에 바로 접근하는 것 같죠?
val fruit = Fruit()

fruit.name = "Apple"
val name = fruit.name // name = "Apple"

Getter와 Setter가 자동으로 구현된다고 했지만, 실제로는 위와 같이 프로퍼티에 접근해요.

fruit.name = "Apple"처럼, fruit.name에 값을 할당하려 하면 Setter가 호출되고, val name = fruit.name처럼 fruit.name의 값을 조회하려 하면 Getter가 호출돼요.
놀랍지 않나요?

저는 getXXX이나 setXXX처럼 메서드를 호출하는 방식이 가독성이 좋지 않다고 느꼈기 때문에, Kotlin에서 위와 같이 프로퍼티에 직접 접근하는 듯한 방법이 마음에 들었어요.

// 값을 수정하지 못하게 하려면?
class Fruit(
    val name: String
)

// 외부에서 접근하지 못하게 하려면?
class Fruit(
    private var name: String
)

프로퍼티의 값을 수정하지 못하게 하려면 val 키워드를 사용하면 돼요.
val 키워드를 사용할 경우 외부에서 Getter만 사용할 수 있게 된답니다.

만약 아예 접근 자체를 막고 싶다면, 접근지정자를 private으로 지정하면 돼요.
Kotlin에서는 기본 접근지정자가 public이란 것도 참고로 알고 계시면 좋을 것 같아요.

마치며

Kotlin에는 위와 같이 다양한 문법을 추가로 제공해요.
어려워서 이해가 힘들거나, 중요하지 않아서 생략한 많은 문법들이 더 존재한답니다.

여러분도 Kotlin을 통해 코드의 가독성을 향상시켜보는건 어떨까요?
