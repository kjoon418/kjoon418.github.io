실무에서 받는 요청은 항상 모호하다.
문제를 제대로 이해하기도 전에 해결하려 하면, 바람직한 방법보다 익숙한 방법을 사용하게 된다.
요구사항을 단계별로 구체화하며 설계하자.

이번 시간엔, 다음 순서 중 Core Entities 정의 단계를 살펴보자.

  1. 기능/비기능 요구사항 정의: 무엇을 만들어야 하는지 구체화한다.
  2. Core Entities 정의: 시스템이 사용할 핵심 객체를 정의한다.
  3. API 설계: 요구사항마다 ‘무엇을 어떻게 호출하면 어떻게 처리하고 응답할지’ 정한다
  4. HLD: 동작하는 시스템을 설계한다.
  5. Deep Dive: 시스템이 비기능 요구사항까지 충족하도록 개선한다.

무엇을 하는가

앞에서 요구사항을 정의했으니, 이제 요구사항을 위해 시스템이 주고받거나 저장할 핵심 객체를 정의하자.

왜 정의해야 할까?

Core Entities를 정의하지 않으면 어떻게 될까?
사용자-서버-저장소의 흐름은 표현할 수 있어도, 무엇을 저장하고 무엇을 조회하는지를 설명하긴 어려워진다.

세부 스키마는 고민하지 말자

Core Entities의 모든걸 정의할 필요는 없다.
이름과 한 줄 설명 정도만 정의하자.

지금 모든 스키마를 정의하려 하면, 시스템이 어떻게 동작할지 설계하기도 전에 시간을 다 쓰게 된다.

당장 필요한 객체만 정의하자

기능 요구사항을 정의할 때, 당장 설계하지 않을 범위 밖 기능도 정했을 것이다.
