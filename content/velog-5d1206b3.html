설계가 중요한 이유

우리는 약속한 기능을 제공하는 동시에, 언제 변경될지 모르는 요구사항에 맞게 시스템을 수정해야 한다
심지어는 미래에 있을 변경을 예측하는 것은 불가능에 가깝다

그렇기 때문에, 변경에 대비하고 변경의 여지를 남겨 놓는 설계가 필요하게 된다

도메인 모델

1. 도메인이란?

사용자가 프로그램을 사용하는 대상 분야를 의미한다
다르게 말하면, 소프트웨어를 이용해 해결하고 싶은 문제 영역을 의미한다

2. 모델이란?

현실(또는 문제 영역)을 단순화한 표현을 의미한다
즉, 복잡성을 해결하기 위해 대상을 추상화하고 단순화한 것이다

3. 도메인 모델이란?

위에서 서술한 도메인의 정의와 모델의 정의를 연결하면 쉽게 이해할 수 있다

도메인 모델이란, 문제 영역에 관한 지식을 선택적으로 단순화하고 의식적으로 구조화한 형태이다

객체지향과 도메인 모델

1. 연결완전성

객체지향은 도메인을 모델링하는 기법과 프로그래밍하는 기법이 동일하다
즉, 도메인 모델링에서 사용한 객체와 개념을 프로그래밍 설계의 객체와 클래스로 매끄럽게 변환할 수 있다

이러한 특성을 연결완전성이라고 한다

2. 가역성(Reversibility)

위에서 설명했듯, 객체지향은 도메인의 모델링 기법과 프로그래밍 기법이 동일하다
이는, 코드의 변경으로부터 도메인 모델의 변경 사항을 유추할 수 있게 만든다

객체지향에서는 코드의 수정이 곧 모델의 수정이 된다
연결완전성의 역방향(코드에서 모델로의 매끄러운 흐름)으로도 볼 수 있는 이러한 특성을 가역성이라고 한다
