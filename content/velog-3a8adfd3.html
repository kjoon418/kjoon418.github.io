개요

우테코 프리코스의 오픈 미션으로 나만의 프레임워크를 만들어보았다.

프레임워크를 만들다보니 당연히 리플렉션을 사용해야만 해결할 수 있는 경우가 몇 있었는데, 리플렉션이라는 개념에 대해 아예 모르고 있던 탓에 상당 부분을 AI를 통해 해결해야만 했다.

AI를 사용하더라도, 내가 잘 아는 분야에서 사용하는 것과 모르는 분야에서 사용하는 것의 차이는 매우 크다고 생각한다.
그동안 리플렉션 개념이 너무 어려울까봐 도전을 미루기만 했는데, 이 경험을 계기로 리플렉션을 이해해보고, AI의 도움 없이 코드를 작성할 수 있는 정도로 성장해보고자 한다.

리플렉션이란?

"반사하다", "되돌아보다"라는 뜻의 Reflect에서 유래되었다.

프로그램이 실행 중에 자기 자신의 구조를 들여다보고 그 구조를 변경/조작할 수 있는 기능을 의미한다.

리플렉션을 통해 클래스, 메서드, 필드 등의 메타데이터를 런타임에 동적으로 조사하고 사용할 수 있다.

클래스의 메타데이터

1. 메타데이터 조회하기

// 1. 클래스에서 찾는 방법: .class
Class<MyClass> classData = MyClass.class;

// 2. 인스턴스에서 찾는 방법: getClass()
MyClass instance = new MyClass();
Class<? extends MyClass> classData = instance.getClass();

// 3. 문자(패키지 경로)로 찾는 방법: Class.forName
Class<?> classData = Class.forName("hello.world.MyClass");

클래스의 메타데이터는 Class라는 클래스로 표현된다.
또한, 위와 같은 방법으로 획득할 수 있다.

2. Class의 클래스 정보 관련 메서드

모두 Class 클래스의 인스턴스 메서드다.

메서드설명
String getName()패키지를 포함한 이름을 반환한다.
String getSimpleName()패키지를 제외한 이름을 반환한다.
Package getPackage()패키지 정보를 반환한다.
String getPackageName()패키지 이름을 반환한다.
Class<? super T> getSuperclass()부모 클래스 정보를 반환한다.
만일 Class가 가리키던 클래스가 Object, 인터페이스, 기본 타입(int 등), void이라면 null을 반환한다.
Class<?>[] getInterfaces()직접 구현한 인터페이스 정보를 반환한다.
boolean isInterface()인터페이스인지 여부를 반환한다.
boolean isEnum()enum인지 여부를 반환한다.
boolean isAnnotation()애노태이션인지 여부를 반환한다.
int getModifiers()수정자(접근 제어자 + 비 접근 제어자)에 대한 정보를 숫자 형태로 반환한다.
수정자에 대한 정보는 Modifier 클래스의 정적 메서드로 조회할 수 있다.
(ex. Modifier.isPublic 등)

getModifiers를 이용하면 수정자를 조회할 수 있는데, 수정자는 다음과 같이 분류할 수 있다는 것도 참고로 알아두자.

  1. 접근 제어자(접근 지정자): public, protected, default, private
  2. 비 접근 제어자: static, final, abstract 등

메서드를 조회하고 호출하기

메서드에 대한 메타데이터는 Method 객체로 표현된다.

0. Class의 Method 관련 메서드

메서드설명
Method[] getMethods()상위 클래스에서 상속 받은 메서드를 포함해, 모든 public 메서드를 반환한다.
해당 클래스에서 선언된 메서드라 하더라도, public이 아니라면 반환하지 않는다.
Method[] getDeclaredMethods()해당 클래스에서 선언한 모든 메서드를 반환한다.
접근 제어자에 상관없이 모두 반환한다.
상위 클래스에서 상속된 메서드는 포함하지 않는다.
Method getDeclaredMethod(String name, Class<?>… parameterTypes)이름과 파라미터 타입이 일치하는 메서드를 반환한다.

1. 정적 메서드 호출(기존 방식)

MyClass instance = new MyClass();

instance.hello("Hello world!");

우리가 일반적으로 사용하는 메서드 호출 방식이다.
코드를 직접 수정하지 않는 이상, 메서드를 호출하는 곳은 항상 정적이다.
(해당 코드를 실행할 땐 항상 instance.hello 메서드가 호출된다)

이를 정적 메서드 호출이라고 부른다.

2. 동적 메서드 호출(Method 활용)

Class<MyClass> myClass = MyClass.class;
String methodName = "hello";

// 메서드 이름과 파라미터 타입들을 통해 메서드를 찾는다
Method helloMethod = myClass.getDeclaredMethod(methodName, String.class);

// 메서드를 실행할 인스턴스와 파라미터를 전달해 메서드를 실행한다
helloMethod.invoke(helloInstance, "Hello world!");

Method의 메타 데이터를 기반으로 메서드를 호출하는 방식이다.
메서드 이름과 파라미터 정보에 따라, 어떤 메서드를 호출할지가 동적으로 결정된다.

이를 동적 메서드 호출이라고 부른다.

Method는 단순히 메타데이터이기 때문에, 그 자체로는 메서드를 실행할 수 없다.
따라서, 어느 인스턴스의 메서드를 호출할 것인지를 같이 지정해 주어야 한다.

참고로 메서드의 접근 지정자가 private인 경우엔 method.setAccessible(true)를 통해 접근 허용 설정을 해 주어야 한다.
그렇지 않으면 IllegalAccessException이 발생한다.

Field 사용하기

필드에 대한 메타데이터는 Field 객체로 표현된다.

0. Class의 Field 관련 메서드

메서드설명
Field[] getFields()상위 클래스에서 상속 받은 필드를 포함해, 모든 public 필드를 반환한다.
해당 클래스에서 선언된 필드라 하더라도, public이 아니면 반환하지 않는다.
Field[] getDeclaredFields()해당 클래스에서 선언한 모든 필드를 반환한다.
접근 제어자에 상관없이 모두 반환한다.
상위 클래스에서 상속된 필드는 포함하지 않는다.

1. 필드 값 수정하기

User user = new User();
Class<? extends User> userClass = user.getClass();

// User.name 필드에 접근한다
Field nameField = userClass.getDeclaredField("name");

// private 필드라면 이처럼 접근을 허용해야 한다
nameField.setAccessible(true);

// 인스턴스와, 수정할 필드 값을 전달한다
nameField.set(user, "New Name");

위와 같이 필드에 접근해서 값을 수정할 수 있다.

private 필드에 setAccessible(true) 없이 접근하면 IllegalAccessException이 발생하니 주의하자.

생성자를 통해 인스턴스 만들기

생성자에 대한 메타데이터는 Constructor 객체로 표현된다.

0. Class의 Constructor 관련 메서드

메서드설명
Constructor<?>[] getConstructors()접근지정자가 public인 모든 생성자를 반환한다.
Constructor<T> getConstructor(Class<?>… parameterTypes)접근 제어자가 public이면서 파라미터 정보와 일치하는 생성자를 반환한다.
Constructor<T>[] getDeclaredConstructors()선언된 모든 생성자를 반환한다.
접근 제어자에 상관없이 모두 반환한다.
Constructor<T> getDeclaredConstructor(Class<?> paremeterTypes)선언된 생성자 중 파라미터 정보와 일치하는 생성자를 반환한다.
접근 제어자에 상관없이 반환한다.

생성자는 상속 개념이 없으므로, 부모 타입의 생성자는 아무 관련도 없다.

1. 생성자를 탐색해 인스턴스 생성하기

Class<MyClass> myClass = MyClass.class;

Constructor<MyClass> constructor = myClass.getDeclaredConstructor(String.class);
constructor.setAccessible(true);

String constructorArgument = "Hello World!";
MyClass instance = constructor.newInstance(constructorArgument);

Constructor의 newInstance 메서드를 통해 인스턴스를 생성할 수 있다.

생성자 역시 접근 지정자가 private일 경우 setAccessible(true)가 필요하다.

리플렉션을 사용할 때의 주의사항

기본적으로, 리플렉션은 캡슐화를 위배하므로 객체지향 원칙을 위반한다.
이에 따라, 리플렉션을 남발하면 유지보수 난이도가 크게 올라가고, 캡슐화 위반으로 인한 버그를 마주하기 쉽다.

리플렉션은 가급적 테스트나 라이브러리 개발에 사용하고, 애플리케이션 코드에서 사용하는 것을 지양하자.

마치며

리플렉션에 대해 기초만 공부한 것이지만, 그 기초 자체는 매우 단순하다.
지금까지 겁 먹고 학습하지 않은 자신이 한심할 정도다.

물론 리플렉션을 제대로 사용하기 위한 심화 과정은 매우 복잡하겠지만, 사실 지금 학습한 메서드와 객체만으로도 대부분의 상황을 해결할 수 있을 것 같다.

이후에 이를 기반으로 나만의 편리한 라이브러리를 직접 만들어보고, 그 과정에서 리플렉션 심화 기술을 공부해 봐야겠다.
