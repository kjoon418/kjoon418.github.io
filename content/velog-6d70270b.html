예외를 처리해보자


Spring Security를 사용해본 사람은 모두 알 것이다.
모든 예외에 403 응답이 나가는 공포... 클라이언트에서 버그가 터지면 원인을 찾아 발로 뛰는 불편함...

나는 Spring에서 전역 예외도 어노태이션으로 추상화 해뒀을 거라고 생각했고, 너무나 당연하게도 존재했다.

어떻게?

@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

	@ExceptionHandler(NoHandlerFoundException.class)
    public ResponseEntity<String> handleNotFound(NoHandlerFoundException exception) {
        log.trace("[ERROR RESPONSE] handleNotFound", exception);

        return ResponseEntity.status(HttpStatus.NOT_FOUND).body("존재하지 않는 엔드포인트입니다");
    }
    
}

@ControllerAdvice와 @ExceptionHandler를 조합해보자.

@ExceptionHadnler는 특정 예외가 발생할 경우 호출되는 메서드를 지정한다.
@ControllerAdvice는 @ExceptionHadnler와 같은 로직이 모든 컨트롤러에 적용되도록 한다.

즉, 위 예시에서는 모든 컨트롤러 단에서 NoHandlerFoundException이 발생시 handleNotFound 메서드를 호출하고, HTTP 응답으로 handleNotFound 메서드의 반환 값을 전달한다.

@ControllerAdvice 대신 @RestControllerAdvice를 사용하면, 반환값을 자동으로 JSON/XML 형태로 직렬화해준다.
